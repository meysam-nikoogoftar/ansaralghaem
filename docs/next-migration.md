# مهاجرت تدریجی به Next.js

ورودی مشترک `http://127.0.0.1:3000` است. `frontend-next` پوستهٔ Next و `frontend` اپ مستقل Vite است. مسیرهای موجود در App Router اولویت دارند؛ مسیرهای باقی‌مانده با fallback rewrite به Vite می‌روند. API و media مستقیماً به Django ارسال می‌شوند.

## اجرای محلی

در سه ترمینال جدا:

```sh
# Django: با تنظیمات معمول پروژه روی 8000 اجرا شود
cd frontend
npm ci
npm run dev
```

```sh
cd frontend-next
npm ci
npm run dev
```

صفحهٔ `/migration` متعلق به Next است. `/` و مسیرهای فعلی همچنان متعلق به Vite هستند. همیشه اپ را از پورت 3000 باز کنید تا localStorage احراز هویت و تنظیمات روی یک origin باقی بمانند.

## انتقال هر بخش

1. صفحه و وابستگی‌های موردنیاز را در `frontend-next/app` منتقل کنید؛ کامپوننت‌های دارای state، window یا localStorage به مرز `use client` نیاز دارند.
2. لینک‌های عبور بین دو اپ باید `<a href>` یا navigation کامل مرورگر باشند. React Router و Next Link فقط درون اپ خودشان استفاده شوند. هنگام انتقال مسیر، لینک‌های React Router ورودی آن مسیر را نیز اصلاح کنید.
3. API را با آدرس نسبی `/api` فراخوانی کنید. منطق توکن فعلی فقط در مرورگر قابل استفاده است؛ برای SSR احراز هویت باید جدا طراحی شود.
4. دسترسی مستقیم، refresh، بازگشت مرورگر، ورود، تم و خطاهای همان مسیر را بررسی کنید؛ سپس route قدیمی را حذف کنید.

برای بازگشت یک مسیر به Vite، صفحهٔ آن را از App Router بردارید. فعلاً catch-all در Next نسازید چون fallback مهاجرت را می‌پوشاند.

## استقرار

دستورهای اجرایی و معیارهای بررسی فاز صفر در [phase-zero.md](phase-zero.md) آمده‌اند.

هر دو اپ باید مستقل اجرا شوند. Next را با `npm run build` و `npm start` اجرا کنید. Vite را build کنید و خروجی `dist` را پشت یک وب‌سرور با SPA fallback به `index.html` قرار دهید (Vite dev server برای production نیست). `LEGACY_ORIGIN` باید به همان وب‌سرور و `API_ORIGIN` به Django اشاره کند و هنگام build پوسته تنظیم شود. مسیرهای `/_next` برای Next رزرو هستند. تغییر origin یا انتقال لینک‌ها بدون navigation کامل می‌تواند رفتار متفاوتی ایجاد کند؛ این موارد پیش از هر انتقال بررسی شوند.
